# 修士論文の実験コード

## フォルダー構成と実行PCへの配置

```text
experiment/
  psychopy2022_spectrum1200_nback_lightweight.py       # N-backの起動・設定
  psychopy2022_spectrum1200_arithmetic_lightweight.py  # 暗算の起動・設定
  psychopy2022_spectrum1200_pvsat_lightweight.py       # PVSATの起動・設定
  counterbalance.csv                                 # ID・実験回数の割り当て
  src/                 # 3課題が使用する内部処理
  tests/               # 機器を使用しない自動テスト
  tools/               # 実験後の視線データ解析
  docs/                # 解析の説明資料
  data/                # 新規の実験結果（実行時に自動作成）
```

実行PCには、ルートの課題スクリプト・`counterbalance.csv`・**`src/` フォルダー全体**をこの配置のままコピーしてください。`src/` 内のファイルをルートへ取り出す必要はありません。`tests/`、`tools/`、`docs/` は課題実行には不要です。追加ライブラリのインストールは不要です。

PsychoPy Coderでは、これまでと同じルートの課題スクリプトを開いて実行します。画面番号・課題時間なども、そのスクリプト先頭で変更できます。CSVと保存先は課題スクリプトの場所を基準に解決するため、作業ディレクトリに依存しません。

## ID・実験回数ごとの結果保存

入力したID・実験回数から、`data/<課題>/<ID>/session_<回数>/<日時>/` を作成します。課題名は `nback`、`arithmetic`、`pvsat` です。実験回数は課題ごとに独立して数えます。

```text
data/
  nback/AFX/session_01/20261026_153000_123456/
    AFX_nback_s01_d03_n02_20261026_153000_123456_trials.csv
    AFX_nback_s01_d03_n02_20261026_153000_123456_gaze.csv
    AFX_nback_s01_d03_n02_20261026_153000_123456_tlx.csv
    ...同じ実行のイベント・メタデータ・ログ・追加ストリーム
  arithmetic/AFX/session_02/20261026_160000_123456/
    AFX_arithmetic_s02_d02_20261026_160000_123456_trials.csv
    ...同じ実行の全記録
```

日時は実行ごとに一度だけ生成します。同じID・回数で再実行しても別の日時フォルダーを作り、日時が衝突した場合は `_02`、`_03` のような連番を付けます。途中で中断した記録もその実行フォルダーへ保存します。入力キャンセル・割り当てエラーでは結果フォルダーを作りません。メタデータの `output_directory`・`output_prefix` に保存先を記録します。

既存の `nback_data/`・`arithmetic_data/` は移動・変更しません。新しい保存先と従来の保存先はGitの追跡対象から除外します。

解析には `tools/tobii_nback_1200hz_features.py` を使用します。引数なしでは `data/nback/` 配下を再帰検索して最新の視線CSVを選び、新しい結果がない場合は従来の `nback_data/` を検索します。暗算・PVSATや特定の実行を選ぶ場合は `--gaze` に視線CSVのパスを指定してください。解析結果は入力CSVと同じフォルダーに保存します。詳細は[解析手順](docs/README_Tobii_Nback_1200Hz_Features_JA.md)を参照してください。

## PVSAT課題の起動と実施方法

`psychopy2022_spectrum1200_pvsat_lightweight.py` をPsychoPy Coderで起動します。被験者IDと**PVSATの実験回数1〜3**から、`counterbalance.csv` の `pvsat_1`〜`pvsat_3` で難易度を自動選択します。例えばAFXの1回目は難易度3、DNVの1回目は難易度1です。プログラムからの `main(participant_id="AFX", session_number=1)` にも対応します。

### 回答方法と提示条件

1〜9の数字を1個ずつ提示します。今の数字と直前の数字の和が**目標値11と一致すれば右矢印、一致しなければ左矢印**で回答します。例えば5→6は右、6→4は左です。累積和ではなく、常に直前の数字と今の数字を足します。同じ数字の連続も許容します。

各ブロックの最初の数字は記憶のみで回答・採点しません。ブロック間で前の数字をリセットします。数字の表示中とその後の注視点表示中に回答でき、最初の矢印キー回答を採用します。締め切りは次の数字の提示予定時刻です。未回答は不正解で、締め切り以降の押下は採用せず次の数字へも持ち越しません。

| 難易度 | 提示開始の間隔 | 数字表示 | 注視点 | 提示数／ブロック | 回答対象／ブロック | 一致試行／ブロック |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 2.5秒 | 0.5秒 | 2.0秒 | 24個 | 23回 | 7回（30.4%） |
| 2 | 2.0秒 | 0.5秒 | 1.5秒 | 30個 | 29回 | 9回（31.0%） |
| 3 | 1.5秒 | 0.5秒 | 1.0秒 | 40個 | 39回 | 12回（30.8%） |

一致割合は回答対象試行が分母です。`TARGET_PROPORTION = 0.30` に回答対象数を掛けて四捨五入した回数を各ブロックに割り当てます。提示数を分母にすると29.2%・30.0%・30.0%です。一致位置をランダム化した後、指定された一致・不一致を満たす数字列を生成し、偶然の一致による増加を防ぎます。

目標値は起動スクリプト先頭の `TARGET_SUM = 11` で変更できます。1〜9の2数の和として設定できる範囲は整数2〜18です。条件を満たす数字列を生成できない設定は開始前にエラーとします。乱数シード・各ブロックのシードを保存するため、数字列を再現できます。追加ライブラリは不要です。

### 3ブロック・270秒、同期とRaw TLX

1ブロックは課題60秒＋休憩30秒です。同じ難易度で**3ブロック**実施し、最後の休憩も含めて270秒です。1セットの提示数は72・90・120個、回答対象は69・87・117回です。最初の同期カウントダウン10秒、校正・説明・Raw TLXの時間は270秒に含みません。

既存課題と同じく、被験者画面はscreen=1の全画面、実施者画面はscreen=0の960×640ウィンドウ、`waitBlanking=False`、通常最大5Hz更新です。被験者には数字と注視点を表示し、課題中の正誤フィードバックは出しません。実施者にはID・回数・難易度・目標値・提示間隔・進行・直近の回答とRT・回答対象試行の正答率を表示します。

同期は各ブロックの**課題60秒の開始・終了**です。開始予定は0・90・180秒、終了予定は60・150・240秒です。初回は開始前、次ブロックは休憩の最後の10秒、終了は課題の最後の10秒にカウントダウンし、合図は1秒間表示します。最後の数字も通常どおり表示・採点し、課題・休憩を延長しません。手動マーカーの入力は実施者が行います。270秒終了後、Tobiiの記録を停止・確定してから、3ブロック全体を対象とするRaw TLXに回答します。

### PVSATの保存内容

出力先は `data/pvsat/<ID>/session_<回数>/<日時>/` です。例：`AFX_pvsat_s01_d03_<日時>_trials.csv`。再実行時は別フォルダーへ保存します。

- `*_trials.csv`：全提示を保存します。`stimulus`（今の数字）、`previous_digit`（直前の数字）、`pair_sum`（和）、`target_sum`（目標値）、`response_required`（回答対象）、`is_target`、`expected_key`、`response_key`、`correct`、`rt_seconds` と各提示・受付終了時刻を記録します。
- 最初の記憶用提示は `response_required=0`、直前の数字・和・一致判定・キー・正誤・RTは空欄です。回答対象の未回答は `correct=0`、キー・RTは空欄です。中断された未完了試行は回答とRTがあれば保持し、`completed=0`・正誤空欄で保存します。
- `rt_seconds` は今の数字の提示開始から最初の有効な押下までの時間です。`input_deadline_rt_seconds` は提示遅延を考慮した実際の受付期限、`onset_error_seconds` は提示予定からのずれです。
- `*_events.csv`：提示・回答検出・受付終了・ブロック・同期・記録停止・TLXのイベントを保存します。
- `*_metadata.json`：提示条件、シード、各ブロックの一致数・回答対象に対する割合、提示数、回答対象数、正答数、時刻・フレーム計測・完了状態・保存先を保存します。`completed_trials` は記憶用を含む完了提示数、`completed_response_trials` は完了した回答対象数です。
- `*_tlx.csv`：`task=pvsat`、`blocks=3`、ID・回数・難易度、6尺度とRaw TLXを保存します。N値は空欄です。視線・追加ストリーム・校正データ・ログも他課題と同じ方式で保存します。

試行・イベントCSVは各ブロックの課題終了時・休憩終了時・TLX前・終了処理でも保存します。視線の解析は `python tools/tobii_nback_1200hz_features.py --gaze "data/pvsat/AFX/session_01/<日時>/<プレフィックス>_gaze.csv"` のように指定できます。休憩は前の数字のISIには含めません。

## 暗算課題の起動と実施方法

`psychopy2022_spectrum1200_arithmetic_lightweight.py` をPsychoPy Coderで起動します。計測前のダイアログに被験者IDと**暗算の実験回数1〜3**を入力すると、`counterbalance.csv` の `arithmetic_1`〜`arithmetic_3` から難易度を選択します。N-backの実験回数とは独立して数えます。例えばAFXの1回目は難易度1、DNVの1回目は難易度3です。

| 難易度 | 出題する式 |
| --- | --- |
| 1 | 1〜9の整数2個の加算（例：3 + 7） |
| 2 | 10〜99の整数2個の加算（例：24 + 58） |
| 3 | 100〜999の整数2個の加算（例：123 + 456） |

### 暗算の1セット：3ブロック・36問・270秒

- 1問5秒。式と回答欄を5秒間表示し、その終了時点の入力を自動採点します。
- 1ブロックは12問・課題60秒＋注視点での休憩30秒です。
- 同じ難易度で**3ブロック**実施します。最後の30秒休憩も含めて270秒です。
- 各ブロックで、繰り上がりなし6問・少なくとも1回あり6問を生成して混ぜます。同一ブロック内では左右を入れ替えただけの式も重複させません。ブロック間の再出題は許容します。
- 繰り上がり回数は、各桁から次の桁へ送る回数を数えます。例：59 + 41は2回、999 + 999は3回です。
- 3ブロック目の休憩終了後、Tobiiの記録を停止・確定し、3ブロック全体を対象にマウスでRaw TLXに回答します。

### テンキーの操作

NumLockをONにしてテンキーを使ってください。入力文字を被験者画面の回答欄に表示します。PsychoPyのキー名に合わせて `num_0`〜`num_9` と通常の数字キー名を受け付けます。

- Backspace：1文字削除。Delete：全削除。
- Enterによる確定は不要です。入力を早く終えても次の問題には進まず、5秒の終了時まで修正できます。
- 最大4桁の整数を入力できます。符号・小数点・演算子は受け付けません。
- 先頭ゼロを含む入力は元の文字列を残し、数値として比較します。空欄は未回答・不正解です。
- 次の問題には前問の入力を持ち越しません。締め切りは押下時刻で判定し、締め切り後の入力は採点に反映しません。
- 被験者画面には式と回答欄を表示します。正誤・直近の回答・累積正答率は実施者画面に表示します。

### 暗算の画面・同期・記録

被験者はscreen=1の全画面、実施者はscreen=0の960×640ウィンドウを使います。実施者側は `waitBlanking=False`、通常更新は最大5Hzです。実施者画面にはID、暗算の実験回数、難易度、ブロック・問題番号、現在の式と未確定入力、直近の採点結果、最初の入力RT・最終編集RTを表示します。

同期は各ブロックの**課題60秒の開始・終了**に合わせます。最初の開始カウントダウン10秒は270秒の前に置き、次ブロックの開始カウントダウンは休憩の最後の10秒に表示します。終了カウントダウンは課題開始50秒後から表示し、最後の2問も通常どおり入力・採点します。開始・終了合図は実施者側に1秒間表示し、課題や休憩を延長しません。fNIRS・NeXuSの手動マーカー入力と記録開始・停止は実施者が行います。

出力先は `data/arithmetic/<ID>/session_<回数>/<日時>/`、プレフィックスの例は `DNV_arithmetic_s01_d03_<日時>` です。

| 出力 | 主な内容 |
| --- | --- |
| `*_trials.csv` | 試行番号1〜36、ブロック番号、式、加算する数、正答、繰り上がり、入力文字列・数値、未回答、正誤、完了状態、各時刻と提示のずれ |
| `*_input.csv` | 有効な入力・削除操作のキー名、編集後の文字列、問題提示から押下までのRT、検出時のシステム時刻 |
| `*_events.csv` | 同期、問題提示・終了、自動採点、休憩、記録停止、Raw TLXの各イベント |
| `*_metadata.json` | 暗算の条件、割り当て元、ブロック別出題シード・時刻・フレーム計測、予定・実測時間、TLXの完了状態 |
| `*_gaze.csv` ほか | N-backと同じTobiiの視線・選択した追加ストリーム |
| `*_tlx.csv` | `task=arithmetic`、ID・実験回数・難易度、`blocks=3`、6尺度とRaw TLX。N値は空欄 |

`first_input_rt_seconds` は最初に数字を入力するまで、`last_edit_rt_seconds` は最後の有効な入力・削除までの時間です。入力後に全削除しても、最初の入力時刻は残します。5秒固定の自動確定時刻を回答完了のRTとはせず、`auto_submit_us` に別に保存します。

問題は開始前に生成し、メタデータの `block_seeds` で再現できます。試行・イベント・入力履歴は各ブロックの課題終了時と休憩終了時にも保存します。中断した問題は途中入力を残し、`completed=0`、`correct` と `auto_submit_us` は空欄にします。中断・エラー時は計測を終了し、課題を完了していなければRaw TLXへ進みません。

実行PCへの配置は冒頭の構成を参照してください。暗算本体は `src/` の問題生成・計測・割り当て・Raw TLXの処理を読み込みます。

暗算のプログラム呼び出しも `main(participant_id="DNV", session_number=1)` に対応します。視線のオフライン解析は解析スクリプトへ `--gaze "data/arithmetic/DNV/session_01/<日時>/<プレフィックス>_gaze.csv"` を渡せます。`stim_on_us`〜`stim_off_us` は問題の表示区間で、休憩は前問のISIに含めません。

## N-backの起動時の被験者ID・実験回数の入力

`psychopy2022_spectrum1200_nback_lightweight.py` を起動すると、計測画面を開く前に入力ダイアログが表示されます。

1. 被験者ID（英字3文字）を入力します。前後の空白を除去し、小文字は大文字に統一します。
2. **N-backの実験回数1〜4**を選択します。1回は、同じ難易度の6ブロック・540秒とRaw TLXを含む1セットです。
3. `counterbalance.csv` のIDの行と `nback_1`〜`nback_4` の該当列から難易度番号を選び、対応するN値で実行します。

| CSVの難易度番号 | 実行する課題 |
| --- | --- |
| 1 | 0-back（Xがターゲット） |
| 2 | 1-back |
| 3 | 2-back |
| 4 | 3-back |

例えばAFXの1回目はCSV値3なので2-back、DNVの1回目はCSV値1なので0-backです。「実験回数」と、セット中の「ブロック番号1〜6」は別々に表示・保存します。実験回数は実施者が毎回選択します。

未登録IDや不正な回数はメッセージを表示して再入力できます。CSVの欠損・ID重複・難易度の不備は開始前に検出します。キャンセルや入力・割り当てのエラーがある間は、Tobiiの記録や実験データの出力を開始しません。CSV自体の読み取りエラーはダイアログで通知して終了するので、ファイルを修正して再起動してください。

実行PCには、本体と同じフォルダーに `counterbalance.csv` と `src/` フォルダー全体を配置してください。割り当てファイルは作業ディレクトリではなく、本体スクリプトの場所を基準に読み取ります。`PARTICIPANT_ID`・`N_BACK` を直接編集する起動方法は、ID・回数からの選択に置き換えています。

出力プレフィックスにはID・課題・回数・難易度番号・N値・日時を含めます。例：`AFX_nback_s01_d03_n02_<日時>_trials.csv`。メタデータとRaw TLX CSVにも `session_number`、`difficulty_level`、`n_back` を保存します。メタデータには参照したCSV列、対応表、実際の刺激集合と0-backの固定ターゲットも保存します。

## N-back課題の刺激と回答方法

0-backはXと0〜9の数字、1〜3-backは0〜9の1桁の数字を表示します。

- 0-back：Xには右矢印、数字には左矢印で回答します。全被験者・全ブロックでXをターゲットとし、説明画面と実施者画面で案内します。課題中に参照用のXを追加表示しません。
- 0-backの各試行では `TARGET_PROBABILITY=0.30` でXを提示し、それ以外は0〜9から選びます。最初の試行からXが出る可能性があり、導入の非ターゲット試行はありません。各ブロックのXの回数は9回に固定せず、確率によって変わります。
- 1〜3-back：N試行前と一致するターゲットには右矢印、不一致には左矢印で回答します。比較履歴をブロックごとにリセットし、各ブロックの最初のN試行は非ターゲット・左矢印を正解とします。
- 刺激表示中と、その後の注視点表示中に回答できます。各試行の最初の矢印キー回答を採用し、回答がないまま終了した試行は不正解にします。
- キャリブレーションの続行と課題準備の完了はSPACE、中断はESCです。準備完了後、開始同期のカウントダウンを経て自動的に課題が始まります。

試行CSVの回答列は従来の `pressed_space` から `response_key` に変更しました。値は `left`、`right`、未回答の場合は空欄です。`correct` は正解が1、不正解・未回答が0です。`rt_seconds` は刺激提示開始から最初の回答までの時間で、未回答の場合は空欄です。中断された未完了試行は `completed=0` とし、`correct` は空欄のまま保存します。メタデータJSONにも刺激の数字集合と回答キーの対応を保存します。

### 1セットの構成

1回の起動で、入力したID・回数から選ばれた1つの難易度を6ブロック実施します。

| 設定 | 初期値・意味 |
| --- | --- |
| `STIMULUS_SECONDS` | 数字提示0.5秒 |
| `ISI_SECONDS` | 数字提示後の注視点1.5秒。1試行は合計2秒 |
| `N_TRIALS` | **1ブロック内**の試行数30。課題時間60秒 |
| `REST_SECONDS` | 各ブロックの課題後の休憩30秒。最後のブロックにも休憩あり |
| `N_BLOCKS` | 同じ難易度で6ブロック。180試行、課題と休憩の合計540秒 |

6ブロック目の休憩終了後にTobiiの記録を停止・確定し、被験者画面でRaw TLXに回答します。最初の開始カウントダウン10秒、キャリブレーション、説明、質問紙への回答時間は540秒に含みません。次の実験回数に進むときは、再起動してID・回数を入力します。暗算・PVSATは各専用の起動スクリプトを使用します。

予定時刻はセットの最初の数字提示を基準に管理します。ブロックの課題開始予定は0・90・180・270・360・450秒です。実際の提示はモニターのフレームと処理時間の影響を受けるため、実測時刻と予定からのずれも保存します。ブロックごとに異なる数字列を生成し、メタデータの `block_seeds` から再現できます。

## N-backの被験者画面と実施者画面

Windowsのディスプレイ設定を「拡張」にし、モニターを2台接続してください。PsychoPyの画面番号は0から数えます。起動時に画面数と設定番号の重複を確認し、指定した画面が存在しない場合は実験を開始しません。

| 設定 | 初期値・動作 |
| --- | --- |
| `SCREEN_INDEX` | 被験者画面は1、全画面、`waitBlanking=True` |
| `OPERATOR_SCREEN_INDEX` | 実施者画面は0、ウィンドウ表示、`waitBlanking=False`、`checkTiming=False` |
| `OPERATOR_WINDOW_SIZE` | 実施者ウィンドウのサイズは960×640ピクセル |
| `OPERATOR_REFRESH_HZ` | 課題中の実施者画面の更新上限は5Hz |
| `SYNC_COUNTDOWN_SECONDS` | 開始・終了の各合図まで10秒 |
| `SYNC_CUE_SECONDS` | 開始・終了の各合図を1秒間表示 |

画面番号が実際の配置と異なる場合は、スクリプト先頭の設定値を変更してください。両画面はpygletバックエンドを使用します。実施者画面の日本語表示にはWindowsの「Yu Gothic」フォントを指定しています。

実施者側はタイトルバー付きのウィンドウで表示し、他の計測ソフトも操作できます。描画領域を抑えるため、初期サイズを960×640ピクセルにしています。必要に応じて `OPERATOR_WINDOW_SIZE` を変更してください。メタデータの `operator_screen_pixels` には実際のウィンドウサイズ、`operator_fullscreen` には `false` を保存します。

実施者画面には、協力者ID、実験回数、難易度番号、N値、刺激集合、総試行数、刺激表示時間、ISI、ターゲット確率、取得周波数、現在の段階、ブロック番号、ブロック内試行番号、セット全体の完了試行数・経過時間、休憩残り時間を表示します。加えて、直近の完了試行の回答・正誤・反応時間と累積正答率を表示します。1〜3-backの導入試行を含む完了試行を対象とし、未回答は不正解として数えます。完了試行がない場合は「未集計」と表示します。

表示用の文字刺激は再利用し、課題中は被験者画面の描画後に最大5Hzで更新します。同じ表示内容の再描画は省略します。準備段階の変更、同期カウントダウンの秒数変更、マーカー入力合図は即時更新します。

### 手動マーカーによる同期手順

1. キャリブレーションと課題説明を終え、各機器を記録可能な状態にしてからSPACEを押します。
2. Tobiiの記録を開始し、被験者画面に注視点を表示します。実施者画面で最初の開始マーカーまで10秒間カウントダウンします。
3. 最初の数字の提示と同じ開始遷移で「開始マーカーを入力」を表示します。合図に合わせてfNIRS・NeXuSなどへ手動マーカーを入力します。合図の1秒間も被験者側の課題は進みます。
4. 各ブロックの課題開始50秒後から、実施者側で終了まで10秒間カウントダウンします。被験者側は最後の5試行を通常どおり継続し、回答も採点します。
5. 60秒の課題終了時に、被験者画面を休憩注視点に切り替え、実施者側に「終了マーカーを入力」を1秒間表示します。この合図の時間は30秒休憩に含まれます。
6. 次のブロックがある場合、休憩の最後の10秒で次の開始マーカーまでカウントダウンします。休憩終了後、次の数字提示と開始合図へ進みます。
7. 最後の30秒休憩が終わったら記録を停止し、Raw TLXへ進みます。7ブロック目の開始合図は出しません。

各ブロックの課題開始・終了の2回、計12回の合図に合わせて手動マーカーを入力します。同期処理は課題・休憩と並行して自動進行し、追加の待機時間やSPACE操作を挟みません。開始合図中の被験者画面は、以前の注視点待機から**通常の数字提示**に変更しています。

ESCで中断すると途中までの試行とイベントを保存し、両画面を閉じます。課題中断・エラー時はRaw TLXを開始せず、以降の同期合図も表示しません。校正の待機中もESCで中断できますが、実行中のSDK呼び出し自体はその処理が戻るまで待つ場合があります。

### 同期と課題時刻の保存

イベントCSVは既存4列に `block` 列を追加します。ブロック番号は1～6で、セット全体・TLXのイベントでは0です。休憩中の次ブロック開始カウントダウンには、開始する側のブロック番号を付けます。

| イベント | 意味 |
| --- | --- |
| `sync_start_countdown` / `sync_end_countdown` | 開始・終了のカウントダウン表示開始 |
| `sync_start_cue` / `sync_end_cue` | 開始・終了のマーカー入力合図の表示開始 |
| `sync_start_cue_end` / `sync_end_cue_end` | 各合図の表示終了 |
| `set_start` / `set_end` | 最初の数字提示／最後の30秒休憩終了 |
| `task_start` / `task_end` | 各ブロックの60秒課題の開始／終了 |
| `rest_start` / `rest_end` | 各ブロックの30秒休憩の開始／終了 |
| `response_window_end` | 各試行の回答受付終了 |
| `recording_stop` | Tobiiの購読解除完了 |
| `tlx_start` / `tlx_response` / `tlx_end` | 質問紙の提示開始／尺度の回答確定・修正／全尺度回答完了 |
| `experiment_aborted` | ESCによる中断 |

同期イベントは実施者画面の `callOnFlip`、刺激イベントは被験者画面の `callOnFlip` でTobiiのシステム時刻を取得します。実施者画面は `waitBlanking=False` のため、同期イベントはソフトウェア上の描画コールバック時刻です。外部機器へ実際に手動マーカーを入力した時刻や、合図が物理的に発光した時刻を計測するものではありません。

`task_start`・`task_end` はそれぞれ6回記録します。課題区間は同じブロック番号の開始・終了時刻で切り出してください。実施者画面と被験者画面の物理的な同時発光は保証せず、両画面のコールバック時刻を別々に記録します。

試行CSVの `trial` はセット内で一意な1～180です。`block`（1～6）、`trial_in_block`（1～30）、`response_window_end_us`（回答受付終了時刻）、`planned_onset_seconds`（セット開始からの提示予定秒）、`onset_error_seconds`（実際の提示の予定からのずれ）を追加しています。中断試行にも実際に回答受付を打ち切った時刻を記録します。

メタデータにはブロックごとの開始・終了時刻、休憩時刻、完了状態、乱数シード、フレーム間隔要約、セットの予定・実測時間、TLXの完了状態を保存します。`participant_frame_timing` は各60秒課題区間の集計です。課題中の同期描画による遅延は計測対象とし、休憩と最初の待機時間は含めません。課題開始前に中断した場合、要約は `null` です。

試行・イベントCSVは各ブロックの課題終了時、休憩終了時、Raw TLX開始前、終了処理で保存します。解析側は明示的な回答受付終了時刻を用い、30秒休憩や休憩中の同期時間を前の試行のISIとして扱いません。従来形式のCSVも読み込めます。

### Raw TLXの回答と保存

`src/nasa_tlx.py` は、[NASAの尺度定義](https://www.nasa.gov/human-systems-integration-division/nasa-task-load-index-tlx/)を基に、知的・知覚的要求、身体的要求、時間的要求、作業成績、努力、フラストレーションを日本語で1尺度ずつ表示します。実行PCにも `src/` フォルダー全体を配置してください。この日本語文面は原文に基づく説明であり、検証済みの日本語版と称するものではありません。

- 同じ難易度の6ブロック全体の課題について回答します。
- 被験者画面にマウスカーソルを表示し、0～100を5点刻みに選択します。初期状態は未回答で、選択するまで「次へ」で進めません。
- 作業成績は0＝完全に達成できた、100＝全く達成できなかった。他の尺度は0＝非常に低い、100＝非常に高いとします。
- 「戻る」で回答を修正できます。押しっぱなしで次ページの回答が確定しないよう、ボタンの解放を確認します。
- 制限時間はありません。6尺度すべての回答を確定したら、単純平均を `raw_tlx` として保存します。一対比較と重み付けは行いません。
- 回答保存後、被験者に完了メッセージを表示します。実施者がSPACEを押すと両画面を閉じます。

回答は実験データと同じプレフィックスの `*_tlx.csv` に保存します。列は協力者ID、課題、実験回数、難易度番号、N値、ブロック数、回答状態、開始・完了時刻、6尺度の値、`raw_tlx` です。尺度の確定・修正ごとに一時ファイル経由で更新します。0点は有効な回答として保存し、未回答と未完了時の総合スコアは空欄にします。TLX中にESCで中断しても、完了済みの課題データと途中回答を保持します。

Tobiiの記録は最後の休憩終了後に停止し、質問紙の回答中には継続しません。fNIRS・NeXuSの記録開始・停止は、従来どおり実施者が手動で行います。

## 難易度のカウンターバランス表

[`counterbalance.csv`](counterbalance.csv) は、実験協力者10人分のIDと、N-back・暗算・PVSATの難易度の実施順序を固定した割り当て表です。1人につきN-backを4回、暗算とPVSATを各3回実施し、それぞれの難易度を1回ずつ経験します。

### 列と難易度番号

| 列 | 内容 |
| --- | --- |
| `participant_id` | 実験協力者のID。重複しない英大文字3文字 |
| `nback_1` ～ `nback_4` | N-backの1回目～4回目に実施する難易度番号（1～4） |
| `arithmetic_1` ～ `arithmetic_3` | 暗算の1回目～3回目に実施する難易度番号（1～3） |
| `pvsat_1` ～ `pvsat_3` | PVSATの1回目～3回目に実施する難易度番号（1～3） |

実験回数は課題ごとに独立して1から数えます。例えば、N-backを4回終えた後でも、初めて行う暗算は `arithmetic_1` を参照します。1回は1つの難易度で行う実験を意味し、課題中の個々の試行数とは異なります。

CSVの値は難易度を区別する番号です。**N-backの番号は実際のN値ではありません。** N-backでは難易度1・2・3・4を0・1・2・3-backへ、暗算では難易度1・2・3を加算する整数の桁数1・2・3へ、PVSATでは難易度1・2・3を提示間隔2.5・2.0・1.5秒へ対応させます。

### 割り当て方法と均等化の範囲

10人では提示位置を完全には均等にできないため、提示位置の均等さを優先し、その制約内で隣接する難易度の移行回数の偏りを小さくしています。

| 課題 | 順序別の人数 | 各提示位置での各難易度の人数 | 各移行の出現回数 |
| --- | --- | --- | --- |
| N-back | `1→2→4→3`・`3→4→2→1`を各3人、`2→3→1→4`・`4→1→3→2`を各2人 | 2～3人 | 2～3回 |
| 暗算 | 全6順序を各1人に割り当て、`1→3→2`・`2→1→3`・`3→1→2`・`3→2→1`を各1人追加 | 3～4人 | 2～4回 |
| PVSAT | 暗算と同じ順序別人数で、IDへの割り当てを別に行う | 3～4人 | 2～4回 |

「移行」は、同じ協力者の同じ課題内で隣接する難易度の組み合わせを方向付きで数えたものです。例えば `1→2` と `2→1` は別に数えます。N-backでは12種類、暗算・PVSATでは各6種類の移行を対象にしています。

N-backの基本4順序は、提示位置と直前条件の両方を均等化する [Williamsデザイン](https://search.r-project.org/CRAN/refmans/crossdes/help/williams.html) に基づきます。10人分では完全な均等化にはならず、順序効果の除去を保証するものではありません。3課題自体の実施順序や、課題をまたぐ影響のカウンターバランスはこの表では扱いません。

再現手順は次のとおりです。

1. IDを `AFX, BKR, CMT, DNV, EPQ, FRS, GLT, HUW, JXZ, KYV` の順に並べます。
2. 各課題について、上表の人数分の順序リストを作り、難易度番号のタプルとして辞書順に並べます。
3. Python標準ライブラリで単一の `random.Random(20261026)` を作成します。
4. 同じ乱数生成器でN-back、暗算、PVSATの各リストに順に `shuffle` を1回ずつ適用し、各リストをID順に割り当てます。

実験では保存済みのCSVを参照し、起動のたびに順序を生成し直さないでください。

### N-backの割り当て読み取りAPI

`src/experiment_assignment.py` はPython標準ライブラリだけでCSVを読み取り、難易度とN値を返します。通常の起動では本体が入力ダイアログを表示します。テスト等では、本体の `main(participant_id="AFX", session_number=1)` を呼んでも同じCSV検証を通して実行できます。

```python
from pathlib import Path
from src.experiment_assignment import load_nback_assignment

csv_path = Path(__file__).resolve().parent / "counterbalance.csv"
assignment = load_nback_assignment(csv_path, "AFX", 1)
print(assignment.difficulty_level)  # 3
print(assignment.n_back)            # 2（2-back）
```

上記APIはCSVを参照するだけです。実験画面や計測は開始しません。実験回数の自動加算・履歴管理は行いません。
